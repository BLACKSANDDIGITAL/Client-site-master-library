# Accessibility Checklist

## Structure

- [ ] Each page has one main landmark.
- [ ] Header, navigation, main content, and footer are clearly structured.
- [ ] Every page has one clear H1.
- [ ] Headings follow a logical order.
- [ ] Navigation regions have useful labels when more than one navigation area exists.

## Keyboard access

- [ ] Every link, button, form field, menu, accordion, and modal can be used with keyboard only.
- [ ] Keyboard focus is always visible.
- [ ] Focus order follows the visible reading order.
- [ ] No keyboard trap exists.
- [ ] Skip link is available if the site has repetitive navigation.

## Images and media

- [ ] Informative images have helpful alt text.
- [ ] Decorative images use `alt=""`.
- [ ] Alt text does not repeat nearby visible text unnecessarily.
- [ ] Text is not embedded in images when it needs to be read or translated.
- [ ] Videos have captions or transcripts when applicable.

## Forms

- [ ] Every input has a visible label.
- [ ] Labels are programmatically associated with controls.
- [ ] Required fields are identified in text, not color alone.
- [ ] Instructions appear before the user needs them.
- [ ] Errors identify the incorrect field and explain how to fix it.
- [ ] Form success feedback is understandable.

## Visual readability

- [ ] Text and control contrast is readable.
- [ ] Information is not communicated by color alone.
- [ ] Text remains usable at 200% zoom.
- [ ] Layout remains usable at narrow screen widths.
- [ ] Buttons and interactive controls have clear states.
- [ ] Motion is reduced when the visitor prefers reduced motion.

## Final check

- [ ] Test core pages using only keyboard.
- [ ] Test primary contact or booking flow.
- [ ] Test at mobile and desktop sizes.
- [ ] Check focus visibility and form errors.
- [ ] Record known accessibility limitations and a contact method if needed.
